# Карта мира Фазиля Искандера: inventory

Инвентаризация завершена; проверенный пилот охватывает 25 текстов, включая цикл о Чике, «Кутеж трех князей в зеленом дворике» и «Историю молельного дерева». Открыть `site/dist/index.html` или `Открыть атлас.cmd`. Наполнение и обновление: [PILOT.md](PILOT.md). Итоги первого этапа: [INVENTORY_REPORT.md](INVENTORY_REPORT.md). Аудит персонажей и состава корпуса: [CORPUS_AUDIT.md](CORPUS_AUDIT.md).

## Запуск

Python 3.11 или новее, внешние зависимости не нужны.

Разместите распакованные EPUB/FB2 в `corpus/canonical_10vol`, `corpus/alternate_fb2`, `corpus/extra`.

```powershell
python inventory.py
python registry.py
python verify.py
python build_pilot.py
python prepare_review_queue.py
python verify_pilot.py
python verify_review_queue.py
python verify_site.py
python quality_report.py
# Или укажите внешний корпус:
python inventory.py --corpus "D:\Books\Iskander"
```

Результаты: `data/inventory.sqlite` и `data/inventory.json`. SQLite хранит источники, пути, оглавления и текстовые фрагменты. JSON — отчёт текущего запуска, ошибки и кандидаты на проверку. ZIP отмечаются как необработанные: сначала распакуйте их. EPUB читается как ZIP без распаковки на диск.

## Что означает результат

- `Source` — конкретный файл издания с полным SHA-256; одинаковые файлы имеют общий Source, но отдельные SourceFile.
- `TocEntry` — пункт оглавления или раздел FB2, **не утверждённое произведение**. Сборник, роман, глава и примечание требуют классификации.
- `TextFragment` — блок FB2 или текстовый узел XHTML. ID определяется байтами источника и структурным адресом; повторный запуск и перенос файла ID не меняют, изменение издания меняет. Это технические фрагменты, ещё не готовые контекстные окна для LLM.
- `Work` и `WorkSource` — канонический структурный реестр и привязки к источникам. `inventory.py` их не заполняет; `registry.py` строит их по проверенным правилам именно этого десятитомника. WorkDetail хранит тип и родителя, WorkFragment — связь с фрагментами; EditionComparison — отдельную очередь сопоставлений.
- Одинаковые заголовки — только кандидаты. Точное совпадение файлов подтверждается SHA-256. `registry.py` определяет границы по порядку EPUB spine и следующему пункту оглавления того же или более высокого уровня, включая промежуточные файлы продолжения. Проверка границ относится к найденному корпусу: иной EPUB требует повторного анализа правил.

Сравнение вариантов использует множества последовательностей из пяти слов и долю их пересечения отдельно для каждого текста. Это сходство, не confidence и не доказательство одной редакции. Полное совпадение нормализованного текста проверяется отдельно: регистр, ё/е, пунктуация и пробельное оформление игнорируются, границы слов сохраняются. Заголовки исключены только из сравнения. Даже такое совпадение не означает побайтового совпадения или равенства печатных изданий. Поиск ограничен тремя лучшими кандидатами по содержимому плюс одноимёнными записями, поэтому не гарантирует обнаружения всех коротких цитат и вхождений.

База накапливает источники: удаление книги с диска не удаляет запись. Отчёт JSON описывает только текущий скан. Для отдельного снимка используйте новый `--output`. Исходные книги не изменяются. Некорректный XML фиксируется как ошибка; молчаливого восстановления текста нет.

## Проверка реестра после получения корпуса

1. Проверить полноту десяти томов по метаданным, именам файлов и оглавлениям.
2. Классифицировать пункты: произведение / цикл / глава / редакционный материал; задать точные границы в источнике.
3. Сопоставить контрольный набор и extra с основным. Сравнивать полный текст произведения после установления границ, не весь сборник.
4. Отдельно сохранять: точный дубль, различие оформления, вариант редакции, одноимённый другой текст, неразрешённый случай. Нормализация для сравнения не должна заменять исходный текст.
5. Утвердить Work и WorkSource с пояснением решения; приоритет canonical_10vol не доказывает тождество текстов.
6. Выбрать 2–3 связанных произведения по подтверждённому корпусу и запустить пилот Mention → entity resolution → Person → связи → сводные описания.

## Контракт будущего extraction

Mention привязан к TextFragment и диапазону текста. Person создаётся или назначается отдельным решением entity resolution; одинаковое имя недостаточно. Неопределённое назначение допускает несколько кандидатов и сырой JSON модели.

Каждое утверждение, включая роль Appearance и PersonPlace, получает Evidence: Work, Source, TextFragment, точная цитата, структурный location, диапазон символов и версия extraction. Проверять, что цитата буквально соответствует указанному диапазону. Пагинацию не выдумывать: EPUB/FB2 обычно не задают стабильных печатных страниц.

Утверждения отделены от Evidence и редакционной оценки. confidence: explicit / strongly_implied / inferred / uncertain. Хранить также происхождение (текст / интерпретация), статус проверки, альтернативы и противоречащие свидетельства. Значение explicit само по себе не делает автоматически извлечённое утверждение проверенным фактом.

Будущие сущности: Person, Alias, Mention, Appearance, Relation, Evidence, Place, PersonPlace, а также отдельное решение entity resolution и связь утверждение–Evidence многие-ко-многим. Родство имеет направление и тип; совместное появление не означает дружбу. Сводки генерируются после сбора появлений и ссылаются на подтверждающие утверждения. Для режима без спойлеров сохранять порядок раскрытия в произведении уже при extraction.
